## 二、思考题：模型再强也不知道 HSK4 的具体数字怎么办？

### 问题在哪
大模型的「知识」是训练时压缩进参数里的，**具体数字、条文、版本日期这类精确信息最容易记错或编造**（幻觉）。
本课程 W4 就真实发生过：问「HSK4 对词汇量的要求」，云端模型一度答成「每分钟 50 个单词」，
本地 0.5b 更是直接编造。模型不是查字典，它是「凭印象」。

### RAG 的思路（下周 W7 要做的）
```
用户问题 ──▶ 检索知识库（把我准备的文本切片、存向量）──▶ 命中相关片段
                                                        │
                                                        ▼
                              把「片段原文 + 问题」一起喂给模型 ──▶ 模型照着材料答
```
关键变化：模型从「凭记忆答」变成「照着材料答」。材料是我们提供的权威原文，
数字不对时能追溯到具体片段，而不是模型瞎编。

### 我的初步设想
1. **切块**：把等级标准按「级别 + 话题」切成小段（每段一两百字），保留级别标签
2. **建索引**：用 embedding 把每段转成向量（W5 里装的 `nomic-embed-text` 可以用）
3. **检索**：问题来了先找最相关的 3–5 段
4. **回答**：把片段和问题拼进 prompt，并要求「只根据材料回答，材料没有就说不知道」

### 为什么这件事值得做
- 教学场景里「数字/条文/校本题库」都不能靠模型记忆
- 有了知识库，同一套 llm.ask() 就能变成「有依据的助教」，而不是「会编的聊天机器人」
