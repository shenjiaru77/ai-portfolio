## 二、思考题：模型再强也不知道 HSK4 的具体数字怎么办？

### 问题在哪
大模型的「知识」是训练时压缩进参数里的，**具体数字、条文、版本日期这类精确信息最容易记错或编造**（幻觉）。
本课程已真实发生过：
- W4 问「HSK4 对词汇量的要求」，云端模型一度答成「每分钟 50 个单词」；
- W6 测试里本地 0.5b 把「把字句」说成「修辞手法」，还编造出原文没有的阅读题选项。

模型不是查字典，它是「凭印象」。所以**不能把模型答案直接写进教案**。

### RAG 的思路（下周 W7 要做的）
```
用户问题 ──▶ 检索知识库（把片段 A/B/C 切片、存向量）──▶ 命中相关片段
                                                        │
                                                        ▼
                    把「片段原文 + 问题」一起喂给模型 ──▶ 模型照着材料答
```
关键变化：模型从「凭记忆答」变成「照着材料答」。材料是我们提供的权威原文，
数字不对时能追溯到具体片段，而不是模型瞎编。

### 我的初步设想
1. **切块**：片段 A 按段落切；片段 B 按「级别」切（每级一条，带级别标签）；片段 C 按「一词一条」
2. **建索引**：用 embedding 把每段转成向量（W5 装的 `nomic-embed-text` 可用）
3. **检索**：问题来了先找最相关的 3–5 段（例如问 HSK4 词汇量，应命中片段 B 的「HSK 4：约 1200 词」）
4. **回答**：把片段和问题拼进 prompt，并强制要求「只根据材料回答，材料没有就说不知道」

### 预期验证
目前 W6 的 `llm.ask()` 是「裸模型」，问 HSK4 词汇量可能又答错。
W7 加上 RAG 后，同一个问题应稳定返回「约 1200 词」，并且能指出依据来自片段 B。
